# 开发路线图

## 阶段 1：静态 MVP

不接后端、不接真实音乐 API、不接摄像头。完成完整页面、默认 BGM、触摸互动、手势引导蒙层和数据面板。

## 阶段 2：创建与分享

接入 Supabase，实现图片和音频上传、Gift 数据保存、`/gift/[id]` 拉取和复制分享链接。

## 阶段 3：音乐能力

实现 QQ 音乐 / 酷狗链接识别、搜索推荐、mock 解析和默认 BGM 兜底。

当前已完成：本地 mock 音乐库、QQ / 酷狗链接形态识别、歌曲推荐、四方式互斥选歌、10 秒试听、本地音频回选、交互页引导后播放。

### 阶段 3 后续技术路线

- 先保持当前 mock 音乐接口稳定：`parseMusicLink`、`searchMusic`、`getSystemBgms` 这类能力应作为页面和真实服务之间的适配层。
- 接入真实 QQ 音乐 / 酷狗能力时，优先识别平台、歌曲名、歌手、封面等元数据；播放地址可能受版权、登录态或接口限制，必须保留上传音频和系统 BGM 兜底。
- 如果选择第三方音乐 API，先评估可用性、版权边界、调用限制、失败率和是否需要服务端签名代理，再替换 mock 搜索结果。
- 系统 BGM 编辑可作为阶段 3 的独立模块继续开发：先扩充系统 BGM 音色和情绪，再支持速度、音色、旋律组合等轻量参数编辑。
- 每一种音乐来源必须保持排他选择：链接解析、歌曲推荐、上传音频、系统 BGM 中最后明确选中的一首歌，才是礼物最终背景音乐。

## 阶段 4：摄像头手势

接入 MediaPipe Hands，实现摄像头授权、基础手势识别和失败后触摸兜底。

当前已完成（阶段 4）：

- 创作者预览页和收礼人礼物页共用同一套摄像头 / 触摸引导。
- 引导层拆成摄像头优先和触摸兜底两部分。
- 摄像头优先区标题为 `舞动双手，唤醒这片花园`，直接提供 `点击启动摄像头` 按钮。
- 点击按钮后才请求摄像头权限；启动中显示 `正在启动摄像头...`。
- 摄像头授权成功后进入 `摄像头` 模式，页面显示实时摄像头预览。
- 关闭引导后舞台右上角保留小摄像头预览。
- 摄像头画面不保存、不上传，不写入礼物数据。
- 摄像头失败自动保持 `触摸` 模式，并显示触摸教程。
- 摄像头启动先请求前置摄像头，失败后降级请求任意可用摄像头。
- 摄像头手势教学当前为 4 个板块：手掌上下摆动、手掌左右摇晃、张开五指并拢双拳、拇指与食指孔雀形状捏合。
- 数据面板显示当前模式：`摄像头` 或 `触摸`。
- 已接入 MediaPipe HandLandmarker 基础识别。
- 已增加两段式摄像头启动、整手轨迹线、坐标平滑、移动死区和开合防抖。
- 已将轨迹可视化升级为双手统一样式的整手骨架、手掌轮廓、拇指 / 食指高亮点、掌心主控点和掌心轨迹。
- 多手策略改为双手同向融合、路径差异较大时右手优先；无左右手信息时回退到画面中心最近的手。
- 支持最多 2 只手入镜：两只手都用彩色实线显示，方向和高度接近时一起参与控制。
- 高度控制改为掌心 Y 位置，风力控制改为掌心横向速度 + 手掌左右倾斜 + 指尖横摆的复合信号。
- 左右手横向坐标按用户看到的镜像预览统一，左右手向屏幕同一方向移动时风向一致。
- 已增强上下 / 左右灵敏度，但以稳定性为先：高度使用首帧校准的掌心 Y 相对位移和轻量垂直速度辅助，左右在高位 / 低位轻量提高倾斜和指尖横摆权重。
- 已增加单帧变化限制、约 250ms 丢帧保持和双手融合 2 帧缓冲，降低灵敏度提升后的串扰和跳变。
- 已修复开合识别坐标混用问题：开合距离使用真实掌心坐标，左右方向使用镜像后的屏幕坐标。
- 已增加开合候选变化短窗口保护，减少张开 / 握拳动作串扰上下 / 左右指令。
- 开合识别改为整手伸展状态，换色识别改为带释放阈值和冷却时间的捏合状态机。
- 已新增摄像头 / 触摸模式手动切换入口，问号引导按当前触发形式展示规则。

后续待做：

- 真机验证不同浏览器的摄像头权限、拒绝授权、设备占用、手势识别稳定性和触摸兜底。
- 根据真机体验微调捏合距离、张开 / 闭合判定、双手融合阈值和左右复合信号灵敏度。
- 保持摄像头失败兜底为触摸模式，不破坏现有触摸主流程。

## 阶段 5：体验打磨

优化主题、动画、移动端适配、加载态、失败态和分享反馈。

当前已完成（阶段 5）：

- 分享链接复制反馈优化：
  - 预览页和礼物页复制成功后，按钮短暂显示 `已复制`。
  - 复制成功提示文案明确告知可以粘贴转发。
  - 复制失败时提示长按链接或手动选中后复制。
  - 新增 `src/lib/clipboard.ts`，支持剪贴板 API 和 textarea 兜底复制。
- 加载状态补齐：
  - `/create/preview` 草稿读取前显示 `正在整理礼物预览`。
  - `/gift/[id]` 礼物读取前显示 `正在打开这份礼物`。
  - 两个加载提示最短可见约 720ms，避免一闪而过。
  - 新增轻量加载点动画。

后续待做：

- 移动端布局溢出与小屏文本适配，优先排查分享弹窗、底部按钮、数据面板、引导卡和礼物舞台。
- 失败态和空状态优化。
- 四个主题视觉区分强化。
- 花朵、音乐盒和全站 UI 细节精修。
- 动画自然度和舒缓感继续打磨。
