# 阶段验收清单

## 阶段 1 验收

- 首页显示 BloomBeat（花律）。
- 可进入完整制作流程。
- 可选择默认 BGM。
- 可填写称呼和 50 字以内祝福。
- 可将祝福语字号调节到 5px - 20px。
- 可选择 4 个主题。
- 可选择祝福语占比：15%、30%、50%、75%，且占比从页面顶部开始计算。
- 可在 0.5x - 1.2x 范围内调节祝福语多行行距。
- 预览页能看到背景、音乐盒、花朵、祝福流动。
- 交互页祝福语由字符组成波浪线形状并横向流动，不是给文字加波浪下划线。
- 多行祝福语的波浪形状应相互平行，并且流动轨迹有轻微上下跳动感。
- 祝福语字符可轻微独立跳动，但不能破坏整句波浪线轮廓。
- 交互页能在 BloomBeat 音乐盒便签内看到 `给XX的礼物` 或用户自定义称呼对应的标题。
- 音乐盒上方展示多朵花，花从带音符的草地上长出。
- 花园整体位于屏幕视觉中心，花朵张开时不应明显互相遮挡。
- 进入交互页时会尝试默认播放音乐，按钮可暂停；若浏览器拦截自动播放，按钮应提示点击播放。
- 可用触摸控制高度、风力、开合和变色。
- 花朵升高和降低幅度明显，最大和最小状态差异清楚。
- 花朵升高和降低幅度应比最初版本更大。
- 触摸滑动过程中交互应连续响应，不只在松手后响应。
- 单击花朵开合，双击花朵统一换色；双击时第一下不应先触发开合。
- 双击换色时所有花朵应保持同一颜色，并统一随机变成新的颜色。
- 页面不显示上下 / 左右方向辅助按钮。
- 左右滑动时只有花朵随风摆动，草地和音乐盒便签不跟着晃。
- 左右滑动时页面有轻微风吹 / 水波纹式波动效果。
- 音乐控制应显示为喇叭图标；点击喇叭后进入静音，BGM 关闭。
- 喇叭图标位于左下角，不遮挡 BloomBeat 便签。
- 点击喇叭时不应触发花朵开合、换色或其他触摸动效。
- 花朵升高时叶子应跟随升高，不能显得像固定假花。
- 无操作时花朵像风铃绳子一样缓慢、轻柔摆动；左右滑动后根据风向和风力改变摇晃状态。
- 微风 0 时保持轻柔摆动；东风 / 西风数值越大，花朵摇晃弧度越大，且每朵花幅度不完全一致。
- 花朵左右摆动幅度应明显可见，但草地和 BloomBeat 便签保持稳定。
- 微风状态下不同花朵也应有轻微随机感。
- 风力旁边应有循环按钮，点击后回到微风状态。
- 风力显示为 `东风 +X`、`西风 +X` 或 `微风 0`。
- 左上角显示风力、高度、手势状态。
- 首次进入显示手势引导蒙层，3 秒后消失，点击 `?` 可重开。

## 阶段 2 验收

- 可上传图片。
- 用户上传图片后，礼物页背景应变成该图片，并叠加模糊蒙版。
- 上传图片作为背景时，应保留现有泡泡氛围，同时让图片主体明显可见。
- 上传图片超过 H5 可视区域时，内容页应提供展示区域选择控件，支持调整左右和上下位置。
- 交互页背景模糊程度应较上一版减少 50%。
- 未上传图片前，内容页应显示空白背景预览框。
- 上传图片后，内容页应支持调整图片缩放。
- 交互页背景模糊程度应在当前基础上继续减少约 60%。
- 交互页背景模糊程度应在 1px 基础上再次降低约 70%，约为 0.3px。
- 交互页背景模糊程度应在 0.3px 基础上再次降低约 70%，约为 0.09px。
- 用户上传图片后，交互页背景蒙版不应带任意主题色，只保留无色透明蒙版。
- 图片缩放控件文案为 `Zoom in`。
- 图片默认高度填满 H5 画面；缩放只能从 100% 向上放大。
- `Zoom in` 显示为额外放大量：0% 表示默认高度填满屏幕。
- 当 `Zoom in` 为 0% 时，上下位置不可调，默认为 0%。
- 交互页背景模糊程度应为 0.3px。
- 交互页背景蒙版应为当前主题色 30% 透明度。
- 未上传图片前，内容页背景预览应为空白“图片预览栏”，不显示任何图片或主题图。
- 上传图片和上传音频应保存到 IndexedDB 草稿，预览页和生成礼物链接时应读取用户上传资源。
- 可上传 10MB 以内音频。
- 超过 10MB 音频会被拒绝。
- 系统 BGM 文案为“若无音频，可选系统 BGM”，点击每个 BGM 板块可试听对应音色。
- 用户上传自选音频后，播放上传音频，不叠加默认 / 主题 BGM。
- 音量随交互变化：花朵越高声音越大，越矮声音越小；越靠左声音越小，越靠右声音越大。
- 可生成 `/gift/[id]`。
- 生成礼物链接入口应为右下角转发图标，点击后弹出小弹窗。
- 转发图标应为粗线条弧形标志，样式与左下角喇叭按钮一致，并与喇叭按钮左右对称。
- 转发图标应位于礼物画面内部右下角，不遮挡下方“返回编辑 / 礼物效果”按钮。
- 弹窗中只有一个主按钮：未生成时为“生成礼物链接”，生成后变为“复制链接”。
- 新窗口打开链接可看到同一份礼物。
- 收礼人不能编辑内容。
- 新用户打开生成后的礼物链接，只进入交互页面，不进入选歌、传图、编辑流程。
- 不需要登录。

## 阶段 3 验收

- 粘贴 QQ 音乐 / 酷狗链接后能识别平台。
- 成功时展示歌曲名、歌手、封面。
- 失败时有明确提示。
- 搜索关键词能展示推荐列表。
- API 不可用时展示内置推荐。
- mock 示例链接可展示解析成功。
- 所有失败情况都能继续选择默认 BGM。

## 阶段 4 验收

- 礼物页显示摄像头授权引导。
- 同意权限后进入手势模式。
- 摄像头画面不保存、不上传。
- 手势状态会更新数据面板。
- 摄像头失败自动进入触摸模式。
- 摄像头引导层应显示诊断信息：安全来源、浏览器摄像头能力、权限状态和最近错误。
- 使用局域网 HTTP 手机地址时，应显示需要 HTTPS / 安全来源，并保留触摸模式。
- 拒绝摄像头授权或摄像头被占用时，应显示对应失败提示，最近错误应可用于判断原因，且不阻断触摸互动。

### 阶段 4 真机调参验收（stage-7+）

- 摄像头模式下礼物页右下角（或移动端左下角）应出现 `调参` 浮标；折叠 / 展开可见。
- 调参面板应展示 FPS、手数（0/1/2）、融合模式、捏合比、张开分、当前高度 / 风力、最近 30 帧手数分布、首帧延迟、阶段提示。
- 调参面板应提供 20 个阈值滑块（高度 / 速度 / 步长 / 横向 / 倾斜 / 指尖 / 张开 / 捏合 / 双手融合 / 平滑 / 移动判定 / 丢帧保持），滑动应立即生效。
- 阈值应自动写入 `localStorage.bloombeat-gesture-config`；点 `恢复默认` 应清空并回到默认。
- 真机诊断卡应显示设备 UA、摄像头分辨率、首帧延迟、累计已识别帧数；失败时显示错误 stack 首行。
- 调参后真机体验：上下挥动应能调节高度且不卡顿；左右挥动应能调节风力；张开 / 闭合应稳定不闪烁；捏合应能换色；双手相近动作应能融合。

> **HTTPS 来源限制**：手机浏览器仅在 secure context（HTTPS / localhost）下允许摄像头；`192.168.x.x` 局域网 HTTP 永远无法唤起摄像头。详见 `docs/12-gesture-tuning.md`。

## 阶段 5 验收

- 四个主题视觉区分明显。
- 手机端无横向滚动、遮挡、布局溢出。
- 动画自然、舒缓。
- 加载、失败、空状态有清晰提示。
- 分享链接复制有反馈。

### 阶段 5 当前模块验收

- 选歌页未选择音乐时，应显示清晰的空状态说明，提示可用链接、推荐、上传或系统 BGM 继续。
- 选歌页搜索无推荐结果时，应显示明确空状态，而不是只出现零散提示。
- 内容页未上传背景图片时，应说明可以继续使用纯色主题背景。
- 预览页只有礼物保存成功时才生成可复制的转发链接；云端未配置或保存失败时，不应生成会误导用户转发的本机链接。
- 云端未配置或保存失败时，应显示普通用户能理解的提示，例如礼物暂时没有保存成功、请稍后重试。
- 打开不存在的 `/gift/[id]` 时，应显示清晰失败页，并提供 `回到首页` 和 `重新打开` 操作。
- 切换 4 个主题时，内容页主题卡片选中态应跟随各自主题色变化。
- 切换 4 个主题后进入预览页，背景、音乐盒、草地、叶子、音符、花心和数据面板应呈现明显不同的主题气质。
- 未上传自定义图片时，内容页图片预览和最终礼物背景应显示当前主题默认背景图。
- 上传自定义图片后，应优先显示用户上传图；点击 `恢复主题默认背景` 后，应重新显示当前主题默认背景图。
- 祝福语横向流动应更舒缓，不应快速扫屏或跳动过强。
- 花朵上下变化、开合和颜色切换应有柔和过渡，不应突然弹跳。
- 风线、音符和背景粒子应轻柔移动，不应抢走礼物主体注意力。
- 花瓣应有柔和高光，花心应有主题色细节，茎叶应有轻量层次，不应显得扁平。
- 音乐盒应有顶部层次和装饰线，文字仍应清晰可读。
- 全站 UI 细节统一精修：
  - 选歌页和内容页主标题样式应一致（22px、清晰可读），不再使用浏览器默认大号 h1；首页标题仍为更大的引导级标题。
  - 用键盘 Tab 切换输入框 / 按钮时，应看到统一的淡粉 focus 描边，不再出现无焦点指示的输入框。
  - 内容页背景图片上传控件应是与选歌页音乐上传一致的圆角引导框，点击后选择图片，框内显示文件名；点击 `恢复主题默认背景` 后文件名应清空。
  - 首页第一屏应有小型花朵品牌标识和轻柔浮动花瓣，`开始制作` 仍是唯一主操作，没有营销文案或多入口。
  - 窄屏下首页花朵、上传框、标题不应出现横向滚动或遮挡。
- 阶段 5 主要模块（分享反馈、加载态、小屏布局、手机存储容错、AMR / 安全来源提示、数据面板闪动、失败态 / 空状态、四主题区分、主题默认背景、动画舒缓、花朵音乐盒细节、全站 UI 统一精修）均已实现，待用户逐项实机确认。

## 阶段 7 当前收口验收（stage-8 快照前）

- `/create/preview` 应作为最终预览与发布页，页面内可直接看到最终礼物效果。
- `/create/preview` 底部应显示 `返回编辑` 和 `完成并分享`，不再出现重复的 `礼物效果` 主按钮。
- `/create/preview` 右下角应显示祝福弹幕开关；关闭后弹幕层消失，刷新后状态保持。
- 编辑页昵称为 `小满` 时，打开分享弹层默认礼物名应为 `给小满的礼物`。
- 分享弹层应提示用户可以修改礼物名称；修改后礼品卡题目应即时同步。
- 修改分享名称后，旧分享链接应清空，并提示重新生成链接。
- 生成分享链接后，自包含 hash 解码出的 `title` 应等于当前礼物名称。
- 点击复制链接成功后，复制按钮应切换为绿色成功态并显示 `已复制`。
- 背景图片上传提示应为 8MB，不再出现 3MB 文案。
- 内容页修改祝福颜色后，预览页弹幕 computed color 应与所选颜色一致。
- 音量面板应为竖向滑杆；音量为 0 时文案为 `音量 0%`，喇叭图标显示静音叉线。
- `/`、`/create/song`、`/create/content`、`/create/preview`、`/gift/demo`、`/gift/share` 应全部返回 200。

## 阶段 8 建议验收

- Supabase 配置完成后，`完成并分享` 应优先生成 `/gift/[id]` 云端链接。
- 使用另一台设备或无本地草稿的新浏览器打开 `/gift/[id]`，应看到同一份礼物名称、祝福、主题、背景和音乐。
- 上传背景图片和上传音频应保存为云端 URL，而不是依赖本地 Data URL。
- 云端保存失败时，应清晰提示并保留 `/gift/share#bloombeat=...` 兜底能力。
- 微信 / Safari / Chrome 中复制链接和系统分享路径应有明确成功或失败反馈。
