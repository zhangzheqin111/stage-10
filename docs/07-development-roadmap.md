# 开发路线图

## 阶段 1：静态 MVP

不接后端、不接真实音乐 API、不接摄像头。完成完整页面、默认 BGM、触摸互动、手势引导蒙层和数据面板。

## 阶段 2：创建与分享

接入 Supabase，实现图片和音频上传、Gift 数据保存、`/gift/[id]` 拉取和复制分享链接。

## 阶段 3：音乐能力

实现 QQ 音乐 / 酷狗链接识别、搜索推荐、mock 解析和默认 BGM 兜底。

当前已完成：本地 mock 音乐库、QQ / 酷狗链接形态识别、歌曲推荐、四方式互斥选歌、10 秒试听、本地音频回选、交互页引导后播放。

### 阶段 3 后续技术路线

- 先保持当前 mock 音乐接口稳定：`parseMusicLink`、`searchMusic`、`getSystemBgms` 这类能力应作为页面和真实服务之间的适配层。
- 接入真实 QQ 音乐 / 酷狗能力时，优先识别平台、歌曲名、歌手、封面等元数据；播放地址可能受版权、登录态或接口限制，必须保留上传音频和系统 BGM 兜底。
- 如果选择第三方音乐 API，先评估可用性、版权边界、调用限制、失败率和是否需要服务端签名代理，再替换 mock 搜索结果。
- 系统 BGM 编辑可作为阶段 3 的独立模块继续开发：先扩充系统 BGM 音色和情绪，再支持速度、音色、旋律组合等轻量参数编辑。
- 每一种音乐来源必须保持排他选择：链接解析、歌曲推荐、上传音频、系统 BGM 中最后明确选中的一首歌，才是礼物最终背景音乐。

## 阶段 4：摄像头手势

接入 MediaPipe Hands，实现摄像头授权、基础手势识别和失败后触摸兜底。

当前已完成（阶段 4）：

- 创作者预览页和收礼人礼物页共用同一套摄像头 / 触摸引导。
- 引导层拆成摄像头优先和触摸兜底两部分。
- 摄像头优先区标题为 `舞动双手，唤醒这片花园`，直接提供 `点击启动摄像头` 按钮。
- 点击按钮后才请求摄像头权限；启动中显示 `正在启动摄像头...`。
- 摄像头授权成功后进入 `摄像头` 模式，页面显示实时摄像头预览。
- 关闭引导后舞台右上角保留小摄像头预览。
- 摄像头画面不保存、不上传，不写入礼物数据。
- 摄像头失败自动保持 `触摸` 模式，并显示触摸教程。
- 摄像头启动先请求前置摄像头，失败后降级请求任意可用摄像头。
- 摄像头手势教学当前为 4 个板块：手掌上下摆动、手掌左右摇晃、张开五指并拢双拳、拇指与食指孔雀形状捏合。
- 数据面板显示当前模式：`摄像头` 或 `触摸`。
- 已接入 MediaPipe HandLandmarker 基础识别。
- 已增加两段式摄像头启动、整手轨迹线、坐标平滑、移动死区和开合防抖。
- 已将轨迹可视化升级为双手统一样式的整手骨架、手掌轮廓、拇指 / 食指高亮点、掌心主控点和掌心轨迹。
- 多手策略改为双手同向融合、路径差异较大时右手优先；无左右手信息时回退到画面中心最近的手。
- 支持最多 2 只手入镜：两只手都用彩色实线显示，方向和高度接近时一起参与控制。
- 高度控制改为掌心 Y 位置，风力控制改为掌心横向速度 + 手掌左右倾斜 + 指尖横摆的复合信号。
- 左右手横向坐标按用户看到的镜像预览统一，左右手向屏幕同一方向移动时风向一致。
- 已增强上下 / 左右灵敏度，但以稳定性为先：高度使用首帧校准的掌心 Y 相对位移和轻量垂直速度辅助，左右在高位 / 低位轻量提高倾斜和指尖横摆权重。
- 已增加单帧变化限制、约 250ms 丢帧保持和双手融合 2 帧缓冲，降低灵敏度提升后的串扰和跳变。
- 已修复开合识别坐标混用问题：开合距离使用真实掌心坐标，左右方向使用镜像后的屏幕坐标。
- 已增加开合候选变化短窗口保护，减少张开 / 握拳动作串扰上下 / 左右指令。
- 开合识别改为整手伸展状态，换色识别改为带释放阈值和冷却时间的捏合状态机。
- 已新增摄像头 / 触摸模式手动切换入口，问号引导按当前触发形式展示规则。
- 已新增摄像头真机验收诊断信息：引导层显示安全来源、浏览器摄像头能力、权限状态和最近一次错误名，帮助区分 HTTPS / 权限 / 设备占用 / 浏览器不支持等问题。
- 已抽出 `src/lib/gestureConfig.ts`：20 个阈值（高度位移 / 速度 / 单帧步长、横向速度 / 偏移 / 倾斜 / 指尖、边缘权重、wind 单帧步长、张开阈值 / 确认时长 / 过渡保留、捏合触发 / 释放 / 冷却、双手方向 / 高度 / 融合帧数、掌心平滑、移动判定 / 阈值、丢帧保持）集中管理并 localStorage 持久化；GiftExperience 中所有硬编码阈值改读 config。
- 已新增 `src/components/GestureDebugPanel.tsx`：摄像头模式下显示调参浮标 + 折叠面板；展示 FPS、手数、融合模式、捏合比、张开分、当前高度 / 风力、最近 30 帧手数分布、首帧延迟、阶段提示；20 个可调滑块 + 恢复默认按钮；阈值变化通过 `useGestureConfigState` 实时生效。
- 已扩展真机诊断卡：设备 UA、摄像头分辨率、首帧延迟、累计已识别帧数、最近错误 stack 首行，辅助判断 HTTPS / 设备 / 性能问题。

后续待做：

- 真机在不同手机（iPhone Safari / Android Chrome / 微信内置浏览器）上完成摄像头手势验收：手机端仅在 HTTPS 沙箱或 Vercel 部署下能拿到 secure context，局域网 HTTP 永远无法唤起摄像头（浏览器安全策略）。
- 用户使用调参面板微调捏合距离 / 张开判定 / 双手融合阈值 / 左右复合信号灵敏度，根据真机体感向 `gestureConfig.ts` 默认值提交调整。
- 保持摄像头失败兜底为触摸模式，不破坏现有触摸主流程。
- 详见 `docs/12-gesture-tuning.md` 真机调参手册。

## 阶段 5：体验打磨

优化主题、动画、移动端适配、加载态、失败态和分享反馈。

当前已完成（阶段 5）：

- 分享链接复制反馈优化：
  - 预览页和礼物页复制成功后，按钮短暂显示 `已复制`。
  - 复制成功提示文案明确告知可以粘贴转发。
  - 复制失败时提示长按链接或手动选中后复制。
  - 新增 `src/lib/clipboard.ts`，支持剪贴板 API 和 textarea 兜底复制。
- 加载状态补齐：
  - `/create/preview` 草稿读取前显示 `正在整理礼物预览`。
  - `/gift/[id]` 礼物读取前显示 `正在打开这份礼物`。
  - 两个加载提示最短可见约 720ms，避免一闪而过。
  - 新增轻量加载点动画。
- 移动端和本地流程稳定性：
  - 小屏布局、分享弹窗、数据面板和礼物舞台横向溢出已修复。
  - 手机端本地存储、创作流程标记和上传资源保留已做容错。
  - 手机音频入口已明确限制 mp3 / wav / m4a，AMR 会提示不支持。
  - 手机局域网 HTTP 无法唤起摄像头时，会提示需要 HTTPS 安全来源并保留触摸模式。
- 失败态和空状态优化：
  - 选歌页未选择歌曲和无推荐结果时显示明确空状态。
  - 内容页未上传图片时显示纯色主题兜底说明。
  - 预览页只有云端保存成功才生成可转发链接；云端失败时不生成本机伪分享链接。
  - 礼物链接失效 / 本机找不到时显示失败页，并提供返回首页和重新打开入口。
- 四个主题视觉区分强化：
  - 主题数据新增舞台强调色、草地、叶子、音乐盒、音符和花心色。
  - 礼物舞台、音乐盒、草地、音符、数据面板和主题卡片选中态跟随主题变化。
- 主题默认背景图：
  - 新增 `public/theme-backgrounds/` 作为系统主题背景目录。
  - 主题配置新增默认背景图路径、位置和缩放。
  - 背景优先级为用户上传图 > 主题默认图 > 主题渐变。
- 动画自然度和舒缓感打磨：
  - 祝福语横向流动速度降低，波浪跳动幅度减小。
  - 花朵高度、叶子、开合和颜色切换过渡变慢变柔。
  - 风线、音符和背景粒子动画放慢并降低动效强度。
- 花朵和音乐盒细节精修：
  - 花瓣增加柔和高光，花心增加主题色细节。
  - 茎叶增加轻量阴影和叶脉。
  - 音乐盒增加装饰线和顶部层次。
- 全站 UI 细节统一精修：
  - 新增 `.page-title` 统一选歌页 / 内容页主标题样式，与首页 `.hero-title` 区分工具页与引导页层级。
  - 输入框、文本域、下拉框统一 focus 态；主要按钮和操作元素统一 `focus-visible` 描边。
  - 内容页背景图片上传从裸 file input 改为自定义 `.upload-image-box`，与选歌页 `.upload-music-box` 上传控件语言一致。
  - 首页第一屏加入 CSS 五瓣品牌花朵和轻柔浮动花瓣，保持单一 `开始制作` 主操作，不改为营销落地页。

后续待做：

- 在 HTTPS 或正式部署环境中继续阶段 4 真机摄像头手势调参。
- 配置 Supabase 完成阶段 2 真实跨设备分享验收。
- 阶段 3 接真实音乐 API 或扩展系统 BGM 编辑，保持四方式互斥选择。

## 阶段 7：数据流与最终发布页收口

当前已完成（stage-8 快照前）：

- `/create/preview` 已收口为最终预览与发布页，不再要求制作者额外进入“礼物效果”页。
- 最终预览页底部主流程为 `返回编辑 + 完成并分享`。
- 最终预览页右下角提供祝福弹幕开关，状态进入草稿和分享链接。
- 分享弹层默认礼物名为 `给XX的礼物`，其中 XX 来自编辑页昵称；用户可修改，修改后同步礼品卡题目。
- 分享链接生成优先走云端保存；云端未配置时生成 `/gift/share#bloombeat=...` 自包含兜底链接。
- 分享链接复制成功后按钮显示绿色成功态和 `已复制`。
- 背景图片上传限制放宽到 8MB；音频上传限制为 10MB。
- 音量控制改为竖向滑杆，音量为 0 或未播放时显示静音喇叭。
- 内容页祝福颜色、主题、背景、称呼等草稿字段同步写入 localStorage 与 IndexedDB，预览页合并读取，减少旧草稿覆盖新设置的问题。

阶段 7 剩余风险：

- 自包含分享链接无法携带上传音频和 data URL 图片，跨设备分享上传资源仍需阶段 2 Supabase Storage。
- 内置浏览器自动化环境可能无法真实写入系统剪贴板；复制成功态需继续在真实移动端浏览器验证。
- 手机端 8MB 图片和 10MB 音频仍可能触发个别浏览器 localStorage / IndexedDB 容量限制，需真机回归。

## 阶段 8：建议进入云端分享与发布稳定化

建议目标：

- 配置 Supabase 项目、表和 Storage bucket。
- 将上传音频 / 背景图片保存到云端 URL。
- 生成稳定 `/gift/[id]` 分享链接，确保新设备打开能看到同一份礼物和资源。
- 保留当前 `/gift/share#bloombeat=...` 作为云端失败兜底。
- 完成手机端复制链接、系统分享和微信 / 浏览器打开路径验收。
