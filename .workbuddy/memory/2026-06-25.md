## CSS 消失问题修复
- **现象**：手机端截图显示所有按钮变成蓝字下划线链接，页面完全无样式。
- **根因**：`next start` 进程跑的是旧 `.next` 构建产物，CSS hash (`2we01tuxvz8rq.css`) 对应文件只有 21 字节（空文件）。`taskkill` 未正确杀掉旧的 node 进程。
- **修复**：`pkill` → `taskkill //F //IM node.exe` 彻底清进程 → `rm -rf .next` → `npx next build` → `npx next start`（用 npx 而非 `node .bin/next`，后者在 Windows 下 shell wrapper 语法报错）。
- **验证**：CSS 文件 `1aqstgx29dlwr.css` 29KB，含全部样式类名。

## 图片上传"无法识别"修复
- **根因分析**：
  1. `canUseImageFile` 在移动端（微信/QQ 内置浏览器）过于严格：这些浏览器常不给 `file.type`，单纯靠扩展名匹配无 fallback，图片被拒绝。
  2. `saveDraft` 静默丢弃：大图转 base64 后 JSON 超过 4MB 安全线，`backgroundImageUrl` 被静默去掉但无错误提示，用户不知情。
  3. `backgroundPositionY` 默认为 0 不合理（应该 50 居中）。
- **修复内容**：
  1. 新增 `compressImage()` 到 `localGiftStore.ts`：Canvas 等比缩放至 800px 宽 + JPEG 质量 0.75，Data URL 从 ~4MB 降到 ~50KB，不会触发 localStorage 截断。
  2. 放宽 `canUseImageFile`：增加了 `type 为空但 size>0` 的兜底逻辑（移动端图库选择场景），accept="image/*" 已做第一层过滤。
  3. `handleImageUpload` 改用 `compressImage`，提示文字改为"正在压缩图片..."。
  4. `backgroundPositionY` 默认值 0 → 50（与主题默认值一致）。

## 音质修复 + 礼物页全屏 H5 适配
- **音质问题根因**：
  1. 增益公式 bug：`volume / 1000` 应为 `volume / 100`，总输出增益从 ~0.005 提到 ~0.04（8x 提升）。
  2. 无低通滤波：原始振荡器高频毛刺直接输出，音色刺耳。
  3. 无微调谐：所有音符完全同频，缺乏自然合唱感。
- **音质修复**：
  1. `SynthBgmButton` 增益链：`volume / 1000` → `volume / 100`。
  2. `playBgmPreset` 新增 BiquadFilterNode（lowpass, 2800Hz, Q=0.6）过滤高频毛刺。
  3. 每层音色加 ±3 分随机微调谐（`randomDetune`），制造自然合唱效果。
  4. stop 时清理 lowpass 节点。
- **礼物页全屏 H5 适配**：
  1. 新增 CSS 类：`.app-shell-full`、`.phone-frame-full`，使用 `100svh`（移动端地址栏自适应）。
  2. `/gift/[id]` 礼物体验页用 `app-shell-full + phone-frame-full` 替代 `app-shell + phone-frame`。
  3. `.gift-stage` 在全屏模式下 `height: 100svh` + `border-radius: 0`。
  4. 分享弹窗在全屏模式下右对齐 18px（不再依赖 phone-frame 居中计算）。

## 修复：无法生成可转发链接 + 上传音频同设备不播放
- **用户反馈**：1. 方式三上传的音乐文件在礼物交互页不播放；2. 最后不能生成可转发的链接。
- **根因分析**：
  1. 上传音频 base64 后通常几 MB，`saveDraft` 写入 localStorage 时超过 4MB 安全线被静默截断 `audioUrl`，但 window 缓存未同步，导致同设备 demo 模式也读不到。
  2. `encodeDraftToHash` 未剥离 `audioUrl` / `backgroundImageUrl`（均为 base64），导致分享 URL 超长（几 MB），浏览器截断了 URL，分享链接无法打开。
- **修复内容**：
  1. `giftCodec.ts`：`encodeDraftToHash` 编码前自动剥离 `audioUrl` 和 `backgroundImageUrl`（data URL），避免 URL 超长；分享链接打开时自动降级为系统 BGM（含自定义音频的礼物会显示提示横幅）。
  2. `gift.ts`：`saveDraft` 同步写入 `window.__bloombeatPreviewDraft` 缓存；`getDraft` 从缓存恢复被 localStorage 截断的 `audioUrl`/`backgroundImageUrl`。
  3. `gift/[id]/page.tsx`：分享链接打开时若 `songSourceType=upload` 但无 `audioUrl`，显示提示横幅（6秒自动消失）。
  4. `globals.css`：新增 `.audio-hint-banner` 样式。
- **当前隧道**：`https://passport-thought-periodic-prayer.trycloudflare.com`
