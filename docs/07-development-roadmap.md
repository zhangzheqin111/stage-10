# 开发路线图

## 阶段 1：静态 MVP

不接后端、不接真实音乐 API、不接摄像头。完成完整页面、默认 BGM、触摸互动、手势引导蒙层和数据面板。

## 阶段 2：创建与分享

接入 Supabase，实现图片和音频上传、Gift 数据保存、`/gift/[id]` 拉取和复制分享链接。

## 阶段 3：音乐能力

实现 QQ 音乐 / 酷狗链接识别、搜索推荐、mock 解析和默认 BGM 兜底。

当前已完成：本地 mock 音乐库、QQ / 酷狗链接形态识别、歌曲推荐、四方式互斥选歌、10 秒试听、本地音频回选、交互页引导后播放。

### 阶段 3 后续技术路线

- 先保持当前 mock 音乐接口稳定：`parseMusicLink`、`searchMusic`、`getSystemBgms` 这类能力应作为页面和真实服务之间的适配层。
- 接入真实 QQ 音乐 / 酷狗能力时，优先识别平台、歌曲名、歌手、封面等元数据；播放地址可能受版权、登录态或接口限制，必须保留上传音频和系统 BGM 兜底。
- 如果选择第三方音乐 API，先评估可用性、版权边界、调用限制、失败率和是否需要服务端签名代理，再替换 mock 搜索结果。
- 系统 BGM 编辑可作为阶段 3 的独立模块继续开发：先扩充系统 BGM 音色和情绪，再支持速度、音色、旋律组合等轻量参数编辑。
- 每一种音乐来源必须保持排他选择：链接解析、歌曲推荐、上传音频、系统 BGM 中最后明确选中的一首歌，才是礼物最终背景音乐。

## 阶段 4：摄像头手势

接入 MediaPipe Hands，实现摄像头授权、基础手势识别和失败后触摸兜底。

## 阶段 5：体验打磨

优化主题、动画、移动端适配、加载态、失败态和分享反馈。
